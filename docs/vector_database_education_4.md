# Chapter 6. 데이터 검색/응답 정합성 검증 (Retrieval/Response)

## 6.1 데이터 평가 및 검증

### 1) 검색 평가와 응답 평가
RAG 시스템의 품질은 크게 **검색(Retrieval) 평가** 와 **응답(Response) 평가** 두 축으로 나눠 검증한다. 두 축을 분리해서 측정해야 "검색이 잘못됐는지" 또는 "생성이 잘못됐는지"를 구분해 문제를 진단할 수 있다.

```text
[ 질문 ] → [ Retrieval 평가 ] → [ Response 평가 ] → [ 종합 품질 판단 ]
```

- **Retrieval 평가**: 질의와 관련된 문서(근거)가 검색되었는지, 얼마나 정확하고 완전하게 검색되었는지를 본다.
- **Response 평가**: 검색된 근거를 바탕으로 생성된 응답이 얼마나 정확하고, 근거에 충실하며, 질문 의도에 부합하는지를 본다.

### 2) 검색평가 매트릭스
| 유형 | 설명 | 예시 |
|---|---|---|
| Recall@K | 정답 문서가 상위 K개 검색 결과에 포함된 비율 | K=5일 때 정답 문서가 상위 5개 안에 있으면 1, 없으면 0으로 계산해 평균 |
| Precision@K | 상위 K개 검색 결과 중 실제 관련 있는 문서의 비율 | 상위 5개 중 3개가 관련 문서면 Precision@5 = 0.6 |
| MRR (Mean Reciprocal Rank) | 정답 문서가 처음 등장하는 순위의 역수 평균 | 정답이 2번째로 나오면 1/2, 이를 전체 질의에 대해 평균 |
| nDCG (Normalized Discounted Cumulative Gain) | 검색 순위별 관련도에 가중치를 주어 누적 평가 | 상위에 배치된 고관련 문서일수록 높은 점수 부여 |
| Hit Rate | 질의당 정답 문서를 하나라도 찾았는지 여부 | 100개 질의 중 92개에서 정답을 찾으면 Hit Rate = 0.92 |
| Context Precision | 검색된 컨텍스트 중 실제로 답변에 사용된 비율 | 5개 검색 결과 중 2개만 답변 근거로 활용되면 0.4 |
| Context Recall | 정답 생성에 필요한 정보가 검색된 컨텍스트에 얼마나 포함됐는지 | 정답 구성 요소 4개 중 3개가 검색됐으면 0.75 |

### 3) 응답평가 매트릭스
| 유형 | 설명 | 예시 |
|---|---|---|
| Faithfulness (충실도) | 응답이 검색된 컨텍스트(근거)에 얼마나 충실한지, 근거 없는 내용을 지어내지 않았는지 | 근거 문서에 없는 수치를 응답에 포함하면 충실도 낮음 |
| Answer Relevancy | 응답이 질문의 의도에 얼마나 부합하는지 | 질문과 무관한 내용까지 장황하게 답하면 낮은 점수 |
| Correctness (정확성) | 응답 내용이 실제 정답(Ground Truth)과 일치하는지 | 정답이 "5일"인데 "10일"로 답하면 부정확 |
| Hallucination Rate (환각률) | 응답 중 근거 없이 생성된(사실이 아닌) 내용의 비율 | 검색되지 않은 규정을 지어내 답변하면 환각으로 분류 |
| Completeness (완전성) | 정답을 구성하는 요소를 응답이 빠짐없이 포함하는지 | 정답이 조건 3가지인데 응답이 1가지만 언급하면 낮은 완전성 |
| Coherence (일관성) | 동일하거나 유사한 질문에 대해 응답이 일관되게 유지되는지 | 같은 질문을 다르게 표현해도 답이 달라지면 낮은 일관성 |
| Citation Accuracy (근거 인용 정확도) | 응답이 인용한 근거 문서가 실제로 관련이 있는지 | 관련 없는 문서를 근거로 표시하면 인용 정확도 낮음 |

### 4) 응답 평가: 정확도·환각 중심 사례
정확도(Correctness)와 환각(Hallucination)은 응답 평가에서 가장 핵심적으로 다뤄지는 두 축이다. 아래 사례로 차이를 비교해본다.

| 사례 | 질문 | 검색된 근거 | 응답 | 평가 |
|---|---|---|---|---|
| 정확한 응답 | 연차는 최대 며칠 이월 가능한가요? | 휴가 규정 3조: "연차는 최대 5일까지 이월 가능" | 연차는 최대 5일까지 다음 해로 이월할 수 있습니다. | 정확성 높음, 환각 없음 |
| 부정확한 응답(오답) | 연차는 최대 며칠 이월 가능한가요? | 휴가 규정 3조: "연차는 최대 5일까지 이월 가능" | 연차는 최대 10일까지 이월할 수 있습니다. | 근거와 불일치 → 정확성 낮음 |
| 환각 응답 | 육아휴직 중 급여는 어떻게 되나요? | (관련 문서가 검색되지 않음) | 육아휴직 중에는 통상임금의 100%가 지급됩니다. | 근거 없이 생성 → 환각 |
| 완전성 부족 응답 | 퇴사 시 처리해야 할 절차는? | 퇴직 규정: "사직서 제출, 인수인계, 비품 반납 3단계" | 사직서를 제출하면 됩니다. | 일부만 응답 → 완전성 부족 |

- **정확도 문제**는 근거는 올바르게 검색됐지만 응답이 근거 내용을 잘못 반영한 경우다.
- **환각 문제**는 애초에 근거가 없거나 부족한데도 응답이 그럴듯한 내용을 지어내는 경우로, RAG 시스템에서 가장 치명적인 실패 유형으로 꼽힌다.

### 5) 검색응답 평가도: RAG 실패 유형별 평가지표 매핑
"Top Evaluation Metrics for RAG Failure" 등 RAG 실패 사례를 다루는 자료들은 실패 유형별로 어떤 평가지표가 그 실패를 탐지할 수 있는지를 매핑해서 제시한다. 대표적인 실패 유형과 대응 지표는 다음과 같다.

| RAG 실패 유형 | 실패 상황 설명 | 탐지에 적합한 평가지표 |
|---|---|---|
| Missing Content | 컨텍스트에 답할 근거 자체가 없음 | Context Recall, Hit Rate |
| Missed Top Ranked | 정답 문서는 있지만 검색 순위가 낮아 활용되지 않음 | Recall@K, MRR, nDCG |
| Not in Context | 컨텍스트 길이 제한으로 근거가 잘려 나감 | Context Precision, Context Recall |
| Not Extracted | 근거는 검색됐지만 LLM이 답을 추출하지 못함 | Faithfulness, Completeness |
| Wrong Format | 요구된 형식(표, 목록 등)을 따르지 않음 | Answer Relevancy |
| Incorrect Specificity | 답변이 지나치게 일반적이거나 과도하게 구체적임 | Correctness, Completeness |
| Incomplete Answers | 정답의 일부 요소만 응답에 포함됨 | Completeness, Context Recall |
| Hallucination | 근거 없이 사실이 아닌 내용을 생성함 | Faithfulness, Hallucination Rate |

이처럼 실패 유형과 지표를 매핑해두면, 평가 결과가 낮게 나왔을 때 "어떤 지표가 낮은지"를 통해 "어느 단계(검색 vs 생성)에서 어떤 유형의 문제가 발생했는지"를 빠르게 추정할 수 있다.

### 6) 교육 포인트 정리
- 검색 평가와 응답 평가는 서로 다른 매트릭스를 사용하며, 두 축을 분리해서 측정해야 원인을 진단할 수 있다.
- 응답 평가에서는 정확도(근거를 올바르게 반영했는가)와 환각(근거 없이 지어냈는가)을 구분해서 봐야 한다.
- RAG 실패 유형과 평가지표를 매핑해두면 문제 진단과 개선 우선순위 결정이 쉬워진다.
- 평가 결과는 성능/정합성 개선 활동의 입력으로 활용된다.

# 결론
RAG 시스템의 품질은 검색과 응답이라는 두 축으로 나눠 검증해야 하며, 각 축마다 서로 다른 평가 매트릭스를 사용해야 원인을 정확히 진단할 수 있다. 특히 정확도와 환각은 응답 평가에서 가장 중요한 두 기준이며, RAG 실패 유형별로 평가지표를 매핑해두면 품질 저하의 원인을 신속하게 좁혀나갈 수 있다.

교육 현장에서는 다음 관점을 함께 강조하는 것이 중요하다.

- **분리 평가 관점**: 검색 실패와 생성 실패를 구분해서 진단
- **다중 지표 관점**: 하나의 지표만으로 품질을 판단하지 않고 여러 지표를 함께 확인
- **실패 유형 관점**: 실패 유형과 지표를 매핑해 개선 우선순위를 정함

즉, 데이터 검색/응답 정합성 검증은 일회성 테스트가 아니라, 서비스 운영 전 기간에 걸쳐 반복적으로 수행해야 하는 품질 관리 활동으로 이해해야 한다.
