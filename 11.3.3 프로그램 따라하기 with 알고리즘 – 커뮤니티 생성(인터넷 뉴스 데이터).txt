#1. 뉴스 노드간 관계 설정 - Neo4j Browser 에서 Cyper Query 를 직접 실행한다.

이 쿼리는 News 노드 간의 관계를 공유 키워드 기반으로 생성하며, 대량 데이터를 효율적으로 처리하기 위해 batch 처리를 사용한다.
weight 속성으로 노드 간 연결 강도를 측정할 수 있으며, w(weight)는 두 노드가 공유하는 키워드의 수로 계산된다.


CALL apoc.periodic.iterate(
'MATCH (a:News1)-[:Consists_of]->(:NewsKeyword1)<-[:Consists_of]-(b:News1) WHERE id(a) > id(b)
RETURN a, b, count(*) as weight',
'MERGE (a)-[r:Relation]-(b) ON CREATE SET r.w = weight',
{batchSize : 10000})
YIELD batch, operations

  
#2. GDS 메모리 내 그래프 생성 - Neo4j Browser 에서 Cyper Query 를 직접 실행한다.
Neo4j에서 CALL gds.graph.project는 Neo4j Graph Data Science (GDS) 라이브러리를 사용하여 메모리 내에서 분석에 사용할 그래프 데이터 구조를 생성하는 데 사용된다

CALL gds.graph.project(
    'News_Relations',
    'News1',
    {
        Relation: {
            properties: 'w'
        }
    }
);

이 명령어는 Neo4j Graph Data Science (GDS) 라이브러리의 기능을 이용해 데이터베이스 내의 특정 부분 그래프를 인메모리 그래프로 생성하는 과정을 나타낸다. 
각 요소를 자세히 살펴보면 다음과 같습니다:

gds.graph.project 프로시저 호출:
이 프로시저는 기존의 Neo4j 그래프 데이터를 인메모리로 불러와, 빠른 분석이나 다양한 그래프 알고리즘(예: PageRank, 커뮤니티 감지, 최단 경로 등)을 적용할 수 있도록 한다.

'News_Relations':
생성할 인메모리 그래프의 이름이다. 이 이름은 이후 알고리즘 실행 시 그래프를 참조하는 데 사용된다.

'News1':
인메모리 그래프로 불러올 노드의 라벨이다. 데이터베이스 내에서 'News1'라는 라벨을 가진 모든 노드들이 대상이 된다.

관계 설정 { Relation: { properties: 'w' } }:

여기서 'Relation'은 관계의 타입이다.
그 관계에 포함할 속성으로 'w'가 지정되어 있다.
일반적으로 'w'는 가중치(weight)를 나타내며, 그래프 알고리즘(예: 가중치 기반 최단 경로 계산 등)에서 중요한 역할을 한다.

즉, 이 명령어는 데이터베이스에서 'News1' 노드와 'Relation' 관계(관계에 'w'라는 속성이 포함된)를 기반으로 'News_Relations'라는 이름의 인메모리 그래프를 생성하는 역할을 한다. 
이를 통해 복잡한 그래프 알고리즘을 보다 효율적으로 수행할 수 있다.


#3.Page Rank 알고리즘 적용 - Neo4j Browser 에서 Cyper Query 를 직접 실행한다.
페이지랭크란 각 노드의 중요도(랭크)를 계산하는 알고리즘이다. 중요도는 해당 노드로 연결된 관계(엣지)의 수와 가중치(w)에 따라 결정되며, Google의 검색 알고리즘에 사용된 알고리즘으로 유명하다. 
계산되는 방식은 다음과 같다.

. 모든 노드의 초기 페이지랭크 값을 동일하게 설정한다.
. 그래프의 관계(가중치 포함)를 기반으로 각 노드의 중요도를 반복적으로 계산한다.
. 알고리즘이 수렴하거나 최대 반복 횟수에 도달하면 결과를 반환한다.


CALL gds.pageRank.write('News_Relations', 
{maxIterations: 20, dampingFactor: 0.85, relationshipWeightProperty: 'w', writeProperty: 'pagerank'})
YIELD nodePropertiesWritten, ranIterations

위의 실행으로 News1 노드에 Page Rank 항목이 만들어 진다.



#4.커뮤니티 SET 만들기 - Neo4j Browser 에서 Cyper Query 를 직접 실행한다.
Louvain 알고리즘은 그래프에서 커뮤니티(Community)를 탐지하기 위한 알고리즘이며, 커뮤니티는 그래프 내에서 서로 연결 강도(모듈성)가 높은 노드 그룹을 의미한다.

CALL gds.louvain.write('News_Relations', 
{relationshipWeightProperty: 'w', writeProperty: 'community' })
YIELD communityCount, modularity, modularities

시간이 오래 걸릴 수 있지만, 기다리면 각 News1 노드안에 커뮤니티 항목이 만들어 진다.

#5.커뮤니티노드와 뉴스노드와의 관계를 설정 - Neo4j Browser 에서 Cyper Query 를 직접 실행한다.
// Community 노드 생성
MATCH (a:News)
MERGE (c:CommunityN {id: a.community})
RETURN c;
//  ArticleN 노드와 Community 노드 간 관계 생성
MATCH (a:News), (c:CommunityN {id: a.community})
MERGE (c)-[:Parent_Child]->(a)
RETURN a, c;

커뮤니티가 만들어지고, 커뮤니티와 뉴스간의 관계가 만들어 진다.
